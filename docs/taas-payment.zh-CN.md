# TaaS 微信与支付宝支付

## 配置入口

管理员进入「系统配置 → 微信与支付宝配置」。配置保存在 `taas_api/config/payments.json`，保存后即时生效，不会返回已保存的私钥或 APIv3 密钥。私钥输入框留空表示保留原值。

平台地址必须为可公网访问的 HTTPS 地址。反向代理需要将以下回调路径转发至 TaaS 后端，并允许支付平台无需登录访问。配置文件包含凭据，应限制文件访问权限，避免公开或提交至版本库。

## 微信支付

使用微信支付 APIv3 Native 扫码支付。需开通 Native 支付产品，填写 AppID、商户号、商户证书序列号、商户私钥 PEM、32 字节 APIv3 密钥、微信平台公钥 ID / 平台证书序列号和对应的 RSA 公钥 PEM。公钥必须来自微信支付平台，不能填写商户公钥。

若商户使用平台证书模式，可从平台证书提取公钥后填写；服务目前使用手动配置的单个公钥，证书或公钥轮换时需更新配置。

回调：`POST /api/payments/wechat/notify`。服务校验签名、通知时间、平台公钥标识，并解密回调内容，核对 AppID、商户号、币种和订单金额后入账。

## 支付宝

使用支付宝电脑网站支付 `alipay.trade.page.pay`，打开支付宝收银台付款。需开通对应产品，并填写应用 ID、收款账户 UID、应用私钥 PEM 和支付宝公钥 PEM。采用公钥模式和 RSA2 签名。沙箱模式仅供测试，需使用沙箱应用和密钥。

回调：`POST /api/payments/alipay/notify`。服务校验签名、应用 ID、收款账户 UID、交易状态和金额。浏览器返回平台页面不代表付款成功。

## 用户操作与接口

### 支付权限授权

在「角色权限」中分配以下权限。管理员默认拥有全部权限，普通用户默认可创建订单、使用微信/支付宝并查看个人订单。新增权限仅在首次初始化时分配，后续重启不会恢复已撤销的支付权限。

| 权限代码 | 功能 |
| --- | --- |
| `payments.configure` | 读取和修改支付配置 |
| `payments.create` | 创建支付订单 |
| `payments.wechat` | 使用微信支付 |
| `payments.alipay` | 使用支付宝支付 |
| `orders.view` | 查看个人订单和充值记录 |
| `orders.manage` | 查看所有订单及充值统计 |
| `orders.confirm` | 人工确认入账（仅人工渠道） |
| `recharges.manage` | 人工充值 |

「指定用户的支付与订单授权」支持逐项选择继承角色、允许或禁止；用户设置优先于角色。授权保存后后端即时生效，刷新页面更新菜单和按钮。授权支付渠道不代表授权查看所有用户订单，个人订单接口仍校验所属用户。付款通知继续按支付平台签名处理，撤销用户发起支付权限不影响已支付订单入账。

用户授权管理接口：`GET/PUT /api/admin/users/{user_id}/permissions`，需要 `users.manage`。PUT 请求示例：`{"overrides":{"payments.wechat":false,"payments.alipay":true}}`；未提供的项继承角色。

用户在套餐区选择微信或支付宝支付；也可为历史待支付订单继续付款。微信展示二维码，支付宝展示收银台链接。付款后点击「查询支付结果」，到账后刷新余额与订单。

客户端「在线充值与支付」提供套餐选择及两种付款入口。未启用的支付方式显示禁用按钮及原因，不再隐藏入口；管理员完成商户配置后，用户点击「刷新支付状态」即可更新。`GET /api/portal/payment-methods` 返回当前账号可用的方式及原因，不返回商户凭据。

继续支付已有订单必须同时满足：订单状态为 `pending`、订单属于当前用户、账号拥有对应支付权限、管理员已启用该渠道、商户凭据完整，并配置公网 HTTPS 回调地址。历史 `manual` 订单可以继续选择微信或支付宝；选择支付方式后订单渠道会锁定，支付下单失败可重试同一方式。

客户端同时支持「余额支付」。余额支付不依赖微信或支付宝商户配置，要求当前余额不低于订单金额；支付时锁定订单和用户余额，扣减余额、标记订单已支付并记录流水。余额不足时提示所需金额和当前余额，用户可先通过其他可用方式充值后再支付。

余额支付按钮仅在余额大于零且账号拥有 `payments.create` 权限时可用。订单已经发起微信或支付宝支付后不可改用余额支付，避免重复扣款；请继续原支付方式或取消后重新创建订单。

页头「充值 / 支付」按钮打开独立页面 `/taas/payment`，管理员和普通用户均可进入，实际可用支付功能按账号权限控制。未登录时提示先登录。

```text
POST /api/portal/orders                         创建套餐订单
POST /api/portal/orders/{order_no}/pay           发起支付，JSON: {"channel":"wechat"} 或 {"channel":"alipay"}
GET  /api/portal/orders/{order_no}               查询自己的订单
GET  /api/admin/payments/config                 管理员读取配置（隐藏私钥）
PUT  /api/admin/payments/config                 管理员保存配置
```

金额必须大于零且最多两位小数。订单首次选择在线支付渠道后不可切换，需创建新订单才能更换渠道。下单失败时可对原订单重试同一渠道。

支付平台的成功异步通知是在线订单入账依据。入账在 PostgreSQL 事务中锁定订单，校验金额和渠道，记录平台交易号，再更新用户余额及充值流水；重复回调不会重复充值。管理确认接口仅处理人工渠道订单。

新模型组合套餐付款后获得独立订单 Token 额度及有效期，不同时充值钱包；历史余额订单仍按原方式入账。不包含退款、主动查询平台交易或自动对账；若支付平台回调尚未到达，订单仍显示待支付。切换商户配置前，应先处理原商户未完成订单。

## 充值流水

后台人工充值、微信/支付宝成功通知、人工确认订单、余额支付和兑换码均在同一个数据库事务中记录流水。记录包括用户 ID、金额、变更前后余额、业务类型、支付渠道、订单号或备注、平台交易号、时间；人工充值还记录操作员 ID。只有成功结算才记录，失败或待支付订单不计为已充值。

用户可在「充值 / 支付」查看本人的最近 100 笔流水；管理员在「订单与充值」按日期查询最近 200 笔明细，查看微信和支付宝金额及操作员。套餐支付金额与钱包实际增加额分开统计，余额支付作为支出记录，不重复计入充值收入。重复成功回调不会生成重复流水。

升级时根据关联的已支付订单补齐历史支付流水渠道、交易号及原来为零的套餐支付金额；无法追溯的旧人工充值操作员不补造。详细套餐消费规则见 `order-model-routing.zh-CN.md`。

部署时安装 `taas_api/requirements.txt` 中的依赖。商户凭据尚未配置时，两种在线支付方式默认关闭。
