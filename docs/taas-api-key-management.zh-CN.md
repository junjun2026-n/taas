# API Key 启用、禁用与删除

创建 API Key 时，用户端与管理端均提供可搜索的模型多选框，选项来自已启用渠道的模型列表，支持点击「刷新可选模型」更新。不选择表示密钥本身不额外限制模型，实际调用仍受套餐、订单及计费配置约束；选择后仅授权勾选的模型。

用户端「API Key」和管理端「API Key 管理」表格的最后一列提供操作：

- **禁用**：立即阻止此密钥发起新调用，保留密钥、配额、订单关联及消费记录。已开始的调用仍正常结算。
- **启用**：恢复已禁用密钥；仍受用户状态、有效期、配额、模型授权及订单可用额度约束。
- **删除**：永久删除密钥，无法恢复。历史调用和消费记录保留；如存在正在处理的调用，提示先禁用并等待调用结束。

所有操作都需要确认，确认与取消并排显示，成功后表格即时更新。用户只能操作自己的密钥；具备 `keys.manage` 权限的管理账号可以操作其他用户的密钥。后台操作执行时重新校验当前登录用户。

接口：

| 操作 | 接口 | 请求体 |
| --- | --- | --- |
| 禁用 | `PATCH /api/keys/{id}/status` | `{"enabled": false}` |
| 启用 | `PATCH /api/keys/{id}/status` | `{"enabled": true}` |
| 删除 | `DELETE /api/keys/{id}` | 无 |
| 用户端兼容删除接口 | `DELETE /api/portal/keys/{id}` | 无，仅可删除自己的密钥 |

接口使用登录会话 `Authorization: Bearer <登录 token>`，不能使用 API Key 自身来管理密钥。

验证：设置 `PYTHONPATH=taas_api/backend` 后执行 `python -m unittest discover -s taas_api/backend/tests`。覆盖所有者操作、跨用户授权、管理权限、调用中删除保护及不存在的密钥。实际接口验证已覆盖禁用后拒绝调用、重新启用恢复调用、删除后失效以及历史日志保留。
