## 目标定义

本项目目标是使用 Python/FastAPI 独立实现与 new-api 等价的产品能力和主要接口行为，而不是复制 Go 源码。参考项目采用 AGPL-3.0，当前 Python 实现保持 clean-room 方式：依据公开文档、路由和可观察行为重新设计。

“完成”必须同时满足：功能可用、接口行为可验证、数据可迁移、权限完整、异常路径有测试。仅存在菜单、数据库表或空接口不算完成。

## 完成判定

在矩阵中仍存在“未实现”或“部分实现”时，不得宣称已经与 New API 完全相同。本地 `new-api` 目录仅有部署方案，本次通过 GitHub 读取并锁定了上游参考提交；还未部署此提交。逐接口兼容验收需运行双方服务并执行契约、异常路径及并发测试。

## 当前结论

TaaS 已具备用户、RBAC、渠道、模型列表、API Key、用户独立 Base URL、套餐、余额、兑换码、订单、微信/支付宝支付、调用日志和 NiceGUI 管理门户。核心 OpenAI Chat Completions、Models 和 SSE 网关可用。

与 new-api 的主要差距集中在：第三方登录、二次认证、细粒度令牌限制、模型元数据和定价、缓存/推理 Token 计费、协议转换、更多多模态和异步任务、Redis 限流熔断、审计与排行、插件、多数据库及完整管理配置面板。支付目前支持微信/支付宝真实回调，但退款、对账和订阅周期自动结算仍未实现。

## 建议补齐顺序

1. 修正密码存储和统一权限校验；加入账号找回、会话管理及 API Key 编辑/启停/过期限制。
2. 完成模型定价、余额原子预扣与结算、流式 Token 统计和日志。当前充值余额未与网关消耗形成闭环，应优先完成。
3. 完成渠道编辑、测试、模型同步、优先级、加权调度、失败重试和自动禁用。
4. 增加 Responses、Embeddings、Anthropic Messages、Gemini 及协议转换，再扩展音频、图片、重排与任务。
5. 完成订阅、周期额度、更多支付方式、支付主动查询及对账；当前微信/支付宝仅完成代码与本地模拟验证，未完成商户真实交易验收。
6. 增加模型广场、在线 Playground、审计搜索、用户用量图表、Redis 限流和插件市场。

## 官方额外能力

所核查官方 README/路由还包含：用户分组、预填分组、签到与邀请返利、Stripe/Creem/易支付等支付路由、订阅绑定与重置、OAuth 绑定管理、Passkey、2FA、访问令牌作用域、插件版本与市场、模型厂商与元数据管理、上游定价同步、运行实例和系统任务管理。当前 TaaS 没有这些对应业务模块。存在官方路由不代表本次已验证其全部行为，也不代表 TaaS 的微信/支付宝直连与官方支付方式兼容。
