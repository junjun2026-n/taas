# 订单消费与多模型套餐

## 管理员配置

1. 配置启用的 API 渠道及模型价格（免费模型也需要配置零价格）。
2. 在套餐新增或修改窗口设置 Token 总额、有效天数，并从已有模型列表多选添加模型，无需为模型指定类型。保存与取消按钮并排显示。
3. 新配置使用 `model_routes: {"models": ["模型一", "模型二"]}`。`model=auto` 在套餐及 Key 授权范围内，按输入和输出价格之和排序：普通对话和短文选择最低价模型，开发和科学计算选择最高价模型；也可显式指定套餐内的模型。价格只作为路由参考，不代表真实模型能力或参数规模。
4. 历史订单的任务映射及 `synthesis` 第二模型配置仍按原快照执行；编辑旧套餐时会转换为模型列表，后续订单使用新规则，不改变已购买订单。

套餐配置在创建订单时保存快照；后续修改或删除套餐不会改变已创建订单。付款成功后从付款时间开始计算有效期，获得订单独立 Token 额度。新套餐付款不再同时增加钱包余额；余额付款从钱包扣除购买金额。钱包可以通过人工充值和兑换码充值。

升级前的订单保留原余额入账方式，不重复授予套餐额度；原套餐需要管理员补充模型组合后才能新购。未支付、过期、其他用户或额度耗尽的订单不可消费。

## 用户选择

创建 API Key 时选择优先消费订单，也可双击现有 Key 在详情中修改。未选择时从最早付款且尚未过期、仍有额度的订单开始。指定订单耗尽或过期会明确报错，不会偷偷改用其他订单；取消绑定即可恢复自动选择。

本次调用可通过请求体 `order_no` 或请求头 `X-TaaS-Order-No` 覆盖 Key 默认订单（请求体优先），仍必须属于 Key 用户。

```json
{
  "model": "auto",
  "order_no": "你的已支付套餐订单号",
  "task_type": "coding",
  "messages": [{"role": "user", "content": "编写一个 Python 排序函数"}],
  "max_tokens": 1024,
  "stream": false
}
```

省略 `task_type` 时按用户消息关键词和长度进行启发式分类；可能分类不准确，复杂任务建议显式指定。显式模型必须属于订单组合且满足 Key 模型授权。历史任务映射套餐未配置任务模型时仍会报错。

成功返回的响应头包含 `X-TaaS-Order-No`、`X-TaaS-Model`、`X-TaaS-Task-Type`。用户订单表展示额度和有效期，调用记录展示订单号与实际模型。费用列是按模型价格计算的成本参考，套餐调用只扣 Token，不再次扣钱包。

## 当前支持范围

目前支持 OpenAI Chat Completions 纯文本、单候选响应。调用前按输入 UTF-8 字节数加安全余量和输出上限预留额度，防止并发重复使用；输入预估偏保守，接近耗尽时可能需要选择其他订单。预留最多保留 30 分钟，正常完成或异常退出会释放。上游实际用量超过预留上限会拒绝结算并提示核查。

组合输出是串行草稿与核查两阶段，不是任意数量模型并行投票。组合暂不支持工具调用；第二阶段失败时第一阶段已实际消耗的 Token 仍保留在账单。流式输出只流式返回最终模型；上游必须返回 usage 才能完整结算。断流或上游不提供用量时仍需管理员核查，当前不具备离线补账机制。科学计算模型仅提供回答，尚未接入计算执行沙箱。
