# API Key 调用地址

管理员和普通用户创建 API Key 后，会显示并支持复制密钥、Base URL、对话调用地址及模型列表地址，同时提供请求体示例。

双击 API Key 表格中的行，可重新打开详情，查看密钥、所属用户、调用地址、配额和创建时间。普通用户仅能查看自己的密钥，拥有 `keys.manage` 权限的用户可查看其他用户密钥。密钥按需读取，不放入表格行数据。详情接口为 `GET /api/keys/{key_id}`，需登录会话认证。

创建 API Key 时可设置授权模型（逗号分隔）和过期时间。留空模型表示允许全部已配置模型，留空过期时间表示永不过期。过期或未授权模型的请求分别返回 401 或 403；编辑接口 `PUT /api/keys/{key_id}` 支持修改名称、额度、模型范围和过期时间。

默认根据当前访问地址和用户 ID 生成：如用户 ID 为 12，访问 `http://服务器IP:8100/taas`，Base URL 为 `http://服务器IP:8100/users/12/v1`。不同用户路径不同，同一用户的多个密钥使用同一路径。

使用公网域名、反向代理或自定义路径时，可在「系统配置 → API 调用基础地址」填写完整地址，例如 `https://api.example.com/v1`。生成的用户地址为 `https://api.example.com/users/12/v1`。此设置优先于访问地址，留空恢复自动生成。代理必须将用户路径转发至后端；自定义前缀需由代理映射。

用户路径下的模型查询与对话接口都验证 API Key 所属用户，其他用户的密钥返回 403。地址本身不能代替密钥。已有密钥也可使用所属用户路径，原 `/v1` 和 `/api/v1` 接口保留兼容。

接口 `POST /api/keys` 和 `POST /api/portal/keys` 的创建结果包含 `base_url`、`chat_completions_url`、`models_url`。调用时使用请求头 `Authorization: Bearer 你的APIKey`，模型名称填写启用渠道中的模型。
